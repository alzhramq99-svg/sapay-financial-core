# دليل مختبري SApay Beta — نسخة عربية

## 1) نطاق التجربة
هذه نسخة تجريبية خاصة (Private Beta) لاختبار تجربة الاستخدام فقط.
- جميع الأرصدة وعمليات الشحن والتحويل افتراضية داخل قاعدة بيانات الاختبار.
- لا تستخدم أموالاً حقيقية، ولا بيانات بطاقات أو حسابات بنكية.
- لا تمثل SApay في هذه النسخة مؤسسة مالية مرخصة، ولا تنفذ تحويلات مصرفية أو دولية.
- لا تشارك كلمة المرور أو رمز الدخول أو صوراً تحتوي بيانات شخصية.

## 2) الدخول وإنشاء حساب اختبار
1. افتح رابط SApay الخاص الذي يرسله منظم الاختبار.
2. اختر «حساب جديد» ثم أدخل **رمز دعوة Beta خاصاً بك** سلّمه لك منظم التجربة عبر قناة آمنة. كل رمز صالح للاستخدام مرة واحدة فقط؛ لا تضع رمزاً حقيقياً في لقطات الشاشة أو بلاغات GitHub.
3. استخدم بريداً مخصصاً للاختبار وكلمة مرور اختبارية لا تقل عن 12 حرفاً، ولا تستخدم كلمة مرورك الشخصية.
4. تأكد من رفض التسجيل عند غياب الدعوة أو انتهاء صلاحيتها أو إعادة استخدام رمز مستهلك، دون كشف سبب الرفض تفصيلياً.
5. سجّل الدخول، وتأكد من ظهور لوحة المحفظة.
6. سجّل الخروج ثم ادخل مرة أخرى للتأكد من عمل الجلسة.

## 3) سيناريوهات الاختبار
دوّن النتيجة لكل خطوة: ناجح / فشل / غير واضح.

### أ. إنشاء المحفظة
1. أنشئ محفظة SDG.
2. أنشئ محفظة USD منفصلة.
3. تحقق من ظهور العملة ومعرّف كل محفظة والرصيد الابتدائي.
4. أعد تحميل الصفحة وتأكد من بقاء المحافظ ظاهرة.

### ب. الشحن التجريبي
1. اختر محفظة SDG ثم «شحن تجريبي».
2. أدخل مبلغاً صغيراً للاختبار ومرجعاً تجريبياً فريداً.
3. نفّذ العملية وتأكد من تحديث الرصيد وظهور سجل الشحن.
4. لا تكرر المرجع نفسه بقصد إنشاء شحن جديد.

### ج. التحويل التجريبي
1. أنشئ حساب اختبار ثانياً على جهاز/متصفح آخر، وأنشئ له محفظة SDG.
2. شارك مع الحساب الأول معرّف محفظة المستلم فقط، وليس بيانات الدخول.
3. من الحساب الأول اختر «تحويل تجريبي»، وحدد محفظة المصدر SDG.
4. الصق معرّف المستلم كاملاً، وأدخل مبلغاً صغيراً لا يتجاوز الرصيد.
5. تحقق من خصم المبلغ من المصدر وإضافته إلى المستلم وظهور سجل العملية لدى الطرفين.
6. لا تنفذ التحويل إذا كانت العملة مختلفة أو لم تتأكد من معرّف المستلم.

### د. الحالات السلبية
- جرّب مبلغاً أكبر من الرصيد: يجب رفض العملية دون تغيير الرصيد.
- جرّب معرّف محفظة غير صحيح: يجب إظهار رسالة مفهومة وعدم إتمام التحويل.
- حاول فتح لوحة المحفظة بعد تسجيل الخروج: يجب طلب تسجيل الدخول.
- لا تختبر الضغط المتكرر أو إرسال طلبات آلية؛ حدود المعدل موضوعة لحماية الخدمة.

## 4) ما الذي يجب تسجيله؟
لكل ملاحظة، سجّل:
- التاريخ والوقت التقريبي والمنطقة الزمنية.
- نوع الجهاز والمتصفح.
- الخطوات التي سبقت المشكلة.
- النتيجة المتوقعة والنتيجة الفعلية.
- نص رسالة الخطأ كما ظهر، دون رموز دخول أو كلمات مرور.
- لقطة شاشة بعد إخفاء البريد ومعرّفات المحافظ وأي معلومات شخصية.

## 6) حدود النسخة
هذه التجربة ليست اختبار قبول مالي أو اعتماداً أمنياً نهائياً. لا تجرّب ربط بنوك أو شركات اتصالات أو خدمات حكومية، ولا تدخل بيانات مالية حقيقية. الوصول للمختبرين يكون بدعوة خاصة فقط، ويوقف المنظم التجربة عند ظهور خلل يؤثر في الرصيد أو ملكية المحفظة.

## 7) بوابة اختبار iPhone الحقيقي قبل قبول Beta
هذه الخطوات لا تنفّذ من اختبارات GitHub Actions وحدها. نتيجة المحاكي أو البناء غير الموقّع **ليست** نتيجة اختبار جهاز حقيقي.

**الشروط المسبقة:**
- [ ] تحديد الجهاز الفعلي، إصدار iOS، واللغة (العربية والإنجليزية).
- [ ] تجهيز رابط Preview أو نسخة مثبتة صالحة للاختبار؛ **Preview في Safari ليس نسخة iOS أصلية**، ولا يثبت عمل Face ID الأصلي.
- [ ] لتثبيت التطبيق الأصلي: عضوية Apple Developer فعالة وشهادات/ملف توقيع صالحان، ثم IPA موقّع وتوزيع مصرح به عبر TestFlight أو مسار تطوير مصرح. لا ترفع إلى TestFlight دون موافقة المالك الصريحة.
- [ ] تجهيز دعوة اختبار **فريدة** مسبقاً في قاعدة بيانات Beta؛ لا تُدخل رموز حقيقية في GitHub أو المحادثة.
- [ ] التحقق من وجود جدول `beta_invitations` على قاعدة Beta قبل اختبار التسجيل. التغيير في `001_schema.sql` لا يضمن ترقية قاعدة قديمة تلقائياً عندما يكون `DB_AUTO_MIGRATE` معطلاً. لا تُطبَّق ترحيلات قواعد البيانات الحية دون موافقة المالك ونسخة احتياطية.

**حالات القبول الفعلية:**
- [ ] فتح الصفحة كاملة في Safari على iPhone دون شاشة فارغة أو قصّ في الأقسام، وتجربة تغيير الاتجاه RTL/LTR.
- [ ] فتح «حساب جديد»: ظهور حقل رمز الدعوة. الرجوع إلى الدخول: اختفاء الحقل، وعدم إرسال رمز الدعوة مع طلب الدخول.
- [ ] تسجيل حساب Beta بدعوة صحيحة ثم تسجيل الدخول والخروج.
- [ ] رفض الدعوة الناقصة/غير الصحيحة/المنتهية/المستخدمة، وعدم إنشاء مستخدم جديد.
- [ ] مراجعة عرض لوحة المحافظ، دليل الخدمات، زر التوسعة والطي، والتنقل السفلي في شاشة iPhone صغيرة.
- [ ] على **نسخة iOS أصلية مثبتة فقط**: تجربة السماح بـ Face ID، تسجيل الدخول بعد إعادة تشغيل التطبيق، رفض البصمة، وتغيير بصمة الجهاز؛ يجب الرجوع إلى كلمة المرور عند الحاجة.
- [ ] التحقق من أن جميع الأرصدة والمعاملات تجريبية ولا يوجد إرسال أو استقبال أموال حقيقية.

**سجل النتيجة:** اكتب حالة كل بند (PASS / FAIL / BLOCKED)، ووقت الفحص وإصدار iOS ونوع التثبيت (Safari / PWA / App)، دون أسرار أو بيانات مالية. لا تعتبر اختبار iPhone الحقيقي مكتملاً حتى يدوّن مختبر من الجهاز هذه النتائج.
